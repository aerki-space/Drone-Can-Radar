# Drone-Can-Radar

24 GHz 8x8 phased-array FMCW radar on a 50 x 40 mm board for small drones, with a DroneCAN interface.
Design stage: docs, planning scripts, DSDL and hardware-independent firmware modules. No schematic or PCB yet.

## Where things live
- `docs/`: design decisions and the numbers behind them. Numbers come from `tools/*.py`; when assumptions
  change, change them in the script, rerun it and update the doc from its output. Don't hand-edit figures.
- `dsdl/aerki/radar/`: UAVCAN v0 (DroneCAN) DSDL. Vendor message IDs are in 20000-21999. Run
  `python3 tools/validate_dsdl.py` after any change.
- `firmware/lib/`: hardware-independent C99, built and unit-tested on the host (`make -C firmware test`).
  MCU/HAL code goes in a separate target directory later; keep `lib/` free of hardware headers.
- `hardware/element_positions.csv` is generated by `tools/array_calc.py --csv`.

## Conventions
- Sensor frame: boresight +X, right +Y, down +Z. Azimuth positive right, elevation positive up.
  Array element index = row * 8 + col, row 0 at the top, col 0 at the left, seen from the front.
- SI units in code and DSDL (m, m/s, rad); degrees only in parameters and docs.
- C: C99, `-Wall -Wextra -Werror`, no dynamic allocation.
- `TX_EN` defaults to off; never change that default.
- Mark planning estimates as estimates; don't present them as measured performance.

## Checks before committing
```sh
make -C firmware test
python3 tools/validate_dsdl.py
python3 tools/array_calc.py && python3 tools/radar_budget.py
```
